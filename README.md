# Second Brain Gateway — версия 2

Маленький сервис, который принимает от тебя мысль (текст или ссылку), просит DeepSeek разобрать её по схеме «Второго Мозга» и возвращает готовые `.md`-файлы. Файлы сохраняет в Obsidian твой iPhone-шорткат.

**Это отдельный проект, к финансовому боту «Ада» он не относится.**

## Как это работает

```
iPhone (шорткат) ──POST /capture──▶ сервис на Railway ──▶ DeepSeek
        ▲                                   │
        └──── готовые .md (files) ◀─────────┘
iPhone сам кладёт файлы в iCloud → Obsidian/SecondBrain/0-Inbox
```

Что важно знать:

- **Схема v1:** 22 типа заметок (фильм/книга, место, вещь, человек, дело, идея, решение, здоровье, документ…) и 13 сфер жизни. Подробности: `docs/schema.html`.
- **Одна запись — до 10 заметок.** «Серик посоветовал Дюну, а ещё надо позвонить маме» превратится в две заметки. Ответ содержит массив `files`.
- **Режим «без ИИ».** Начни запись с `!` или со слова `секрет:` — текст не уйдёт в DeepSeek, не будет читаться по ссылкам и не запоминается на сервере. Заметка просто сохранится как есть.
- **Ссылки читаются.** Для YouTube берётся название и канал, для остальных https-страниц — заголовок и описание (закрытые и внутренние адреса сервис не открывает).
- **Тексты на сервере не хранятся.** В базе лежит только готовый ответ на 24 часа, чтобы повторная отправка не тратила токены. Потом он стирается. Все заметки живут только в твоём хранилище.
- **Заметка не потеряется.** Если DeepSeek недоступен, заметка сохраняется «как есть» (тег `unprocessed`).
- **Имя файла, дату и свойства делает код, а не нейросеть**, поэтому ИИ не может сломать файл.

Пока поддерживаются **текст и ссылки**. Голос и фото шорткат превращает в текст сам; Telegram и ответы на вопросы по базе — следующие шаги.

## Обновление с версии 1 (если сервис уже работает)

Новых библиотек и переменных не нужно, ключи и токен остаются прежними.

1. Распакуй новый архив.
2. GitHub → твой репозиторий → **Add file → Upload files**. Перетащи **всё содержимое** папки (папки `app`, `tests`, `docs` и файлы рядом). Файлы с тем же именем заменятся. Нажми **Commit changes**.
3. Лишние старые файлы в `app` (если такие появятся) можно удалить через ⋯ → **Delete file**. Критично это только для файлов с тем же именем, а они заменяются сами.
4. Railway сам пересоберёт сервис (1–3 минуты). Статус должен стать зелёным.
5. Открой `https://ТВОЙ-АДРЕС/health`: `{"status":"ok"}`.
6. Старый шорткат продолжит работать: первая заметка по-прежнему приходит в `markdown`/`filename`. Чтобы сохранять **все** заметки из записи, переделай шорткат по части 2.

## Часть 1. Запуск на Railway (один раз, ~15 минут)

### 1.1. Положи проект на GitHub

1. Зайди на github.com → **New repository** → название, например, `second-brain-gateway` → поставь **Private** → **Create repository**.
2. На странице нового репозитория нажми ссылку **uploading an existing file**.
3. Распакуй архив с проектом и перетащи в окно **всё содержимое папки** (папки `app`, `tests` и файлы `README.md`, `requirements.txt`, `Procfile` и т.д.). Нажми **Commit changes**.

> Файл `.env.example` — просто образец, настоящих ключей в нём нет. Свои ключи на GitHub не загружай никогда.

### 1.2. Придумай токен доступа

Это пароль, по которому сервис узнаёт твой шорткат. Он должен быть длинным и случайным. На ноутбуке открой **PowerShell** и выполни:

```powershell
[guid]::NewGuid().ToString("N") + [guid]::NewGuid().ToString("N")
```

Получится строка из 64 символов. Скопируй её и временно сохрани в надёжном месте (например, в менеджере паролей). Это твой `CAPTURE_TOKEN`.

### 1.3. Создай сервис на Railway

Названия кнопок могут немного отличаться, смысл тот же.

1. railway.com → **New Project** → **Deploy from GitHub repo** → выбери `second-brain-gateway`. Railway сам определит Python и запустит сборку (команду запуска он возьмёт из файла `Procfile`).
2. Открой созданный сервис → вкладка **Variables** → добавь переменные:

   | Имя | Значение |
   |---|---|
   | `CAPTURE_TOKEN` | токен из шага 1.2 |
   | `DEEPSEEK_API_KEY` | твой ключ DeepSeek |
   | `DEEPSEEK_MODEL` | `deepseek-v4-flash` (если DeepSeek переименует модель, поменяй здесь) |
   | `DATA_DIR` | `/data` |
   | `APP_TIMEZONE` | `Asia/Almaty` |

3. Добавь **Volume** (постоянный диск), иначе база обнулится при каждом перезапуске: в проекте нажми **+ New** / правый клик по сервису → **Volume** → путь монтирования (Mount path) **`/data`**.
4. Вкладка **Settings** → раздел **Networking** → **Generate Domain**. Получишь адрес вида `https://что-то.up.railway.app`.
5. Дождись, пока деплой станет зелёным (Active/Success).

### 1.4. Проверь, что сервис жив

Открой в браузере `https://ТВОЙ-АДРЕС/health`. Должно появиться `{"status":"ok"}`.

Если вместо этого ошибка, открой в Railway вкладку **Deployments → View logs**. Самая частая причина: не задан `CAPTURE_TOKEN` или он короче 24 символов. Сервис при этом специально не запускается и пишет об этом в логе.

### 1.5. Тестовая заметка с ноутбука

В PowerShell (подставь свой адрес и токен):

```powershell
$h = @{ "x-api-key" = "ТВОЙ_ТОКЕН" }
$body = @{ input_type = "text"; content = "Проверка связи: купить кабель HDMI до пятницы" } | ConvertTo-Json
$r = Invoke-RestMethod -Uri "https://ТВОЙ-АДРЕС/capture" -Method Post -Headers $h `
     -Body ([System.Text.Encoding]::UTF8.GetBytes($body)) -ContentType "application/json; charset=utf-8"
$r.message
$r.files[0].markdown
```

Ожидаемо: сообщение вроде `Дело: Купить кабель HDMI` и готовый Markdown со свойствами, тегами и блоком «Оригинал». Если пишет `ИИ недоступен — заметка сохранена как есть`, сервис работает, но с DeepSeek что-то не так: проверь `DEEPSEEK_API_KEY`, баланс и имя модели.

## Часть 2. Шорткат «Во Второй Мозг» на iPhone

> ⚠️ **Токен будет внутри шортката.** Никогда не делись этим шорткатом (ссылка iCloud, маркетплейс, генераторы шорткатов) и не вставляй токен в чужие сервисы и нейросети. Если токен всё-таки засветился, замени `CAPTURE_TOKEN` в Railway на новый и поменяй его в шорткате.

Открой приложение **«Команды»** → **+** → назови команду **Во Второй Мозг**.

### Шаг 1. Откуда команда принимает данные

1. Нажми на название команды вверху → **Подробнее** (значок ⓘ).
2. Включи **«Показывать в меню Поделиться»**.
3. В строке «Принимает …» оставь только **Текст** и **URL-адреса** (остальное отключи).
4. Для пункта «Если нет входных данных» выбери **Запросить** (тип — текст). Тогда команда сама спросит, что записать, если запустить её с экрана.

### Шаг 2. Уникальный номер заметки

Он нужен, чтобы повторная отправка не создавала дубли.

1. Действие **«Дата»** (Текущая дата).
2. Действие **«Форматировать дату»** → формат **«Другой»** → `yyyyMMdd-HHmmss`.
3. Действие **«Случайное число»** от `100000` до `999999`.
4. Действие **«Текст»**: вставь в него переменные «Отформатированная дата», затем дефис, затем «Случайное число».
5. Действие **«Задать переменную»** → имя `v_id`, значение = результат «Текст».

### Шаг 3. Отправка на сервис

1. Действие **«Получить содержимое URL»**.
2. **URL:** `https://ТВОЙ-АДРЕС/capture`
3. Нажми «Показать больше»:
   - **Метод:** POST
   - **Заголовки:** добавь заголовок `x-api-key` со значением = твой токен.
   - **Тело запроса:** JSON. Добавь поля (кнопка «Добавить новое поле»):

     | Тип | Ключ | Значение |
     |---|---|---|
     | Текст | `capture_id` | переменная `v_id` |
     | Текст | `client` | `ios` |
     | Текст | `input_type` | `text` |
     | Текст | `content` | **«Входные данные команды»** |
     | Число | `revision` | `1` |

   Тип входа указывать не нужно: если пришла одна ссылка, сервис сам поймёт, что это ссылка.
4. Действие **«Задать переменную»** → `v_response` = «Содержимое URL».

### Шаг 4. Если ИИ просит уточнение

1. Действие **«Получить значение для ключа»** → ключ `needs_review_flag` из `v_response`.
2. Действие **«Если»**: «Значение словаря» **равно** `yes`.
3. Внутри «Если»:
   1. **«Получить значение для ключа»** → `review_text` из `v_response`.
   2. **«Запросить ввод»** (текст), в подсказку вставь результат шага выше. Ответ сохрани в переменную `v_answer`.
   3. Ещё раз **«Получить содержимое URL»**: настройки те же, что в шаге 3 (проще всего **продублировать** то действие), но изменённые поля: `revision` = `2`, и добавь поле Текст `user_clarifications` = `v_answer`. Поле `capture_id` остаётся тем же (`v_id`).
   4. **«Задать переменную»** → `v_response` = «Содержимое URL» (она перезапишет старый ответ).
4. **«Конец Если»**.

### Шаг 5. Сохранение всех заметок в Obsidian

В ответе сервиса есть список `files`: одна запись может дать от 1 до 10 заметок. Шорткат должен пройти по списку и сохранить каждую.

1. **«Получить значение для ключа»** → ключ `files` из `v_response`.
2. **«Повторить с каждым элементом»** («Повторить для каждого»). Внутри цикла три действия, и везде источник — **«Элемент повторения»** (Repeat Item), а не `v_response`:
   1. **«Получить значение для ключа»** → `markdown` из «Элемент повторения». Затем **«Задать переменную»** `v_md`.
   2. **«Получить значение для ключа»** → `filename` из «Элемент повторения». Затем **«Задать переменную»** `v_name`.
   3. **«Задать имя»**: в русском интерфейсе читается как «Задать имя **[имя]** для **[объект]**». В поле имени вставь переменную `v_name`, в поле объекта — `v_md`. Расширение `.md` уже есть в имени.
   4. **«Сохранить файл»**: «Спрашивать, где сохранить» выключено; папка iCloud Drive → **Obsidian** → **SecondBrain** → **0-Inbox**; «Перезаписать, если существует» выключено.
3. **«Конец повтора»**.
4. После цикла: **«Получить значение для ключа»** → `message` из `v_response` → **«Показать уведомление»**.

Если в «Сохранить файл» на устройстве не получается выбрать `v_md` как содержимое, поставь перед ним ещё одно «Задать переменную» и сохраняй результат «Задать имя» (его называют «Именованный файл»).

### Режим «без ИИ»

Начни фразу с `!` (например, `! пароль от домофона 4321`) или словом `секрет:`. Текст не пойдёт в DeepSeek и не останется на сервере, но заметка сохранится в хранилище. Уточняющих вопросов в этом режиме нет. Понимай, что до сервера текст всё равно доходит по защищённому каналу, просто сервис его не анализирует и не запоминает. Совсем секретные данные (номера карт, пароли от банков) лучше вообще не записывать через шорткат.

### Проверка

1. Запусти команду, введи: `Серик посоветовал фильм Дюна 2, надо позвонить маме`.
2. Должно прийти уведомление, а в `0-Inbox` появиться 1–2 файла.
3. Открой файл в Obsidian: сверху свойства (тип, статус, сфера, теги), ниже текст и свёрнутый блок «Оригинал».

Если файл сохранился как `.md.txt`, «Задать имя» не применилось: проверь порядок (имя — `v_name`, объект — `v_md`) и что оно стоит **перед** «Сохранить файл».

Если после ответа на уточняющий вопрос сервис возвращает ту же заметку, проверь, что во втором запросе `revision` = **число** 2, а не текст.

## Часть 3. Вопросы к хранилищу, утренняя сводка, голос и фото

> Как это устроено. Заметки хранятся только в твоём хранилище. Шорткат читает их из iCloud и **вместе с вопросом** отправляет сервису. Сервис отдаёт ИИ сжатый список, получает ответ и **ничего не сохраняет**. Заметки с `private: true` (записанные через `!`) отбрасываются сразу, ИИ их не видит. Обычные заметки при вопросе всё же уходят в DeepSeek, имей это в виду.
>
> Заметки, у которых нет свойства `type` (стартовая страница, дашборды, шаблоны), в вопросах не участвуют.

### Команда «Спросить Второй Мозг»

Создай новую команду с таким названием и добавь действия:

1. **«Запросить ввод»** → тип «Текст», вопрос «Что спросить?». Голосом можно, значок микрофона на клавиатуре. Ответ сохрани: **«Задать переменную»** `v_q`.
2. **«Получить содержимое папки»** → выбери папку **SecondBrain** (iCloud Drive → Obsidian). Включи **«Рекурсивно»**: она спрятана за «Показать больше». Если такого переключателя нет, выбери папку `0-Inbox`, а вторым и третьим таким же действием добавь `1-Люди` и `2-Знания`.
3. **«Получить текст из входных данных»** (результат предыдущего шага).
4. **«Объединить текст»**, разделитель **«Новая строка»**. Затем **«Задать переменную»** `v_corpus`.
5. **«Получить содержимое URL»**:
   - URL: `https://ТВОЙ-АДРЕС/ask`
   - Метод **POST**, заголовок `x-api-key` = твой токен.
   - Тело запроса: JSON, два поля типа «Текст»: `question` = переменная `v_q`, `corpus` = переменная `v_corpus`.
6. **«Получить значение для ключа»** → `answer`.
7. **«Показать результат»** (откроется окно с ответом). Можно добавить **«Произнести текст»**, чтобы телефон зачитал ответ.

Примеры вопросов: «какие фильмы планировал на вечер?», «что я обещал Серику?», «что надо сделать по дому на этой неделе?», «когда истекает договор аренды?», «что решил насчёт замка и почему?».

Если ИИ недоступен, команда не сломается, а покажет, что нашлось по словам из вопроса. В ответе также есть `sources_text`: список заметок, на которые опирался ответ. Его можно вывести отдельным шагом «Получить значение для ключа» → `sources_text`.

**Пределы.** Одновременно можно отправить до ~3 млн символов заметок (это несколько тысяч заметок). Если их больше, сервис сам отберёт подходящие по словам вопроса. Чтение тысяч файлов из iCloud на телефоне занимает несколько секунд, это нормально. Когда заметок станет заметно больше, мы вынесем индекс в один файл, и ответы станут быстрее.

### Команда «Сводка дня»

Она нужна именно против забывчивости: показывает просроченное, сегодняшнее и ближайшие 7 дней по делам, событиям, дням рождения, уходу за домом, срокам документов и гарантий, решениям на пересмотр, ожиданиям ответа. **ИИ не нужен**, сводку считает код по свойствам заметок, поэтому она работает всегда.

Действия те же, что в «Спросить», кроме двух отличий: пропусти шаги 1 и 6, в шаге 5 используй адрес `https://ТВОЙ-АДРЕС/digest` и отправляй только поле `corpus`; в конце возьми ключ **`digest`**.

Чтобы сводка приходила сама каждое утро: приложение «Команды» → вкладка **«Автоматизация»** → **+** → **«Время суток»** → 08:00, «Ежедневно» → действие **«Выполнить команду»** → «Сводка дня» → отключи «Спрашивать перед запуском». Результат лучше показывать **«Показать уведомление»**, а не окно.

Сводка опирается на свойства-даты. Поэтому хорошо диктовать сроки словами: «до пятницы», «через неделю»: ИИ переведёт их в даты.

### Голос и фото в «Во Второй Мозг»

Сервис принимает только текст, а превращает в текст сам шорткат средствами iPhone. В начале команды «Во Второй Мозг» (там, где сейчас «Если нет входных данных → Запросить») поставь **«Выбрать из меню»** с пунктами:

- **Написать**: «Запросить ввод» (текст) → результат в переменную `v_content`.
- **Продиктовать**: **«Диктовать текст»** (язык: русский, остановка: «После паузы») → `v_content`.
- **Сфотографировать**: **«Сделать фото»** → **«Извлечь текст из изображения»** → `v_content`. Подходит для чеков, визиток, страниц, записей на доске.
- **Из буфера**: **«Получить буфер обмена»** → `v_content`.

Дальше в «Получить содержимое URL» поле `content` бери из `v_content`. Распознавание речи и текста делает сам iPhone, на сервер уходит уже готовый текст. Если диктовка в твоём регионе недоступна, пользуйся микрофоном на клавиатуре в пункте «Написать».

## Часть 4. Карточки людей (на ноутбуке)

Когда в заметках появляется `[[Серик]]`, отдельной карточки у него нет. Скрипт `tools/vault_people.py` создаёт для каждого названного человека файл `1-Люди/Серик.md` и **собирает в него всё известное**:
- телефоны, почту, день рождения, компанию и другое из заметок типа «Человек» (то, что ты надиктовал о нём);
- внутри карточки Dataview сам показывает его дела, звонки и встречи, всё, где он упомянут, и идеи подарков.

Скрипт ничего не отправляет в интернет и не затирает то, что ты уже вписал. Тело карточки он не трогает, а заполняет только пустые поля. Его безопасно запускать сколько угодно раз.

### Один раз: поставить Python
1. Открой python.org/downloads, скачай установщик для Windows.
2. В первом окне установки **обязательно поставь галочку «Add python.exe to PATH»**, затем **Install Now**.
3. Открой PowerShell и проверь: `python --version`. Должно показать версию 3.x.

### Каждый раз, когда хочешь обновить карточки
1. Положи файл `vault_people.py` в любое место, например на рабочий стол.
2. Узнай путь к хранилищу. При установленном iCloud для Windows это обычно `C:\Users\ТВОЁ_ИМЯ\iCloudDrive\Obsidian\SecondBrain`. Путь можно скопировать из проводника.
3. Сначала пробный запуск, который ничего не меняет:
   ```powershell
   python "$HOME\Desktop\vault_people.py" "C:\Users\ТВОЁ_ИМЯ\iCloudDrive\Obsidian\SecondBrain" --dry-run
   ```
4. Если список разумный, запусти то же самое без `--dry-run`.
5. Подожди, пока iCloud синхронизирует новые файлы на телефон.

Частота: раз в несколько дней или перед важным разговором. Если нужно сделать это одним ярлыком, пришли мне, соберу `.bat`-файл.

## Часть 5. Telegram-бот (вход для записи)

Бот принимает от тебя текст и ссылки, как шорткат: сервис разбирает их по схеме и отвечает «Записал: …». Если нужно, переспрашивает (ответь одним сообщением или `/skip`). Режим «без ИИ» работает так же: начни сообщение с `!`.

**Как заметка попадает в хранилище.** Сервис не может писать в iCloud, поэтому готовые заметки ждут в **очереди** на сервере. Их забирает **ноутбук** (скрипт `tools/vault_sync.py`) или **телефон** (шорткат), кладёт в `0-Inbox`, и только после этого заметка стирается с сервера. Если никто не забрал, заметка удаляется через 45 дней. То есть тексты из Telegram лежат на сервере, пока не будут выгружены (это исключение из правила «ничего не храним»). Спрашивать бота можно командами `/ask`, `/day`, `/week`, `/brief`: они работают по срезу хранилища на сервере (часть 8).

Голос и фото бот пока не принимает. Диктуй с клавиатуры телефона или пришли текст.

### Настройка (один раз, ~15 минут)

**1. Создай бота.** В Telegram найди **@BotFather** → `/newbot` → придумай имя и username (заканчивается на `bot`). BotFather выдаст **токен** вида `123456:ABC...`. Это пароль от бота: никому не показывай и не присылай в чат нейросетям. (Мне он не нужен: токен используется только при одной команде ниже.)

**2. Придумай секрет вебхука.** Это длинная случайная строка (латиница и цифры, от 16 символов). В PowerShell:
```powershell
[guid]::NewGuid().ToString("N")
```
Сохрани результат.

**3. Добавь переменные на Railway** (сервис → Variables):

| Имя | Значение |
|---|---|
| `TELEGRAM_WEBHOOK_SECRET` | строка из шага 2 |
| `TELEGRAM_ALLOWED_USER_IDS` | оставь пока пустой, заполнишь на шаге 5 |

Railway сам перезапустит сервис.

**4. Подключи бота к сервису.** Один раз выполни в PowerShell (подставь свой токен, секрет и адрес):
```powershell
$token  = "ТОКЕН_ОТ_BOTFATHER"
$secret = "СЕКРЕТ_ИЗ_ШАГА_2"
$url    = "https://ТВОЙ-АДРЕС/telegram/webhook"
Invoke-RestMethod "https://api.telegram.org/bot$token/setWebhook" -Method Post -Body @{ url = $url; secret_token = $secret }
```
Должно вернуться `ok : True`. После этого закрой окно PowerShell, токен нигде сохранять не нужно.

**5. Узнай свой Telegram ID.** Напиши боту любое сообщение. Пока список разрешённых пуст, бот ответит «Бот ещё не настроен. Твой Telegram ID: 123456789». Впиши это число в `TELEGRAM_ALLOWED_USER_IDS` на Railway (можно несколько через запятую, например для жены) и дождись перезапуска. Писать боту смогут только они, остальные будут проигнорированы.

**6. Проверь.** Напиши боту «купить кабель HDMI до пятницы». Должен прийти ответ «Записал: …». Команда `/status` покажет, сколько заметок ждут выгрузки.

### Как забирать заметки

**На ноутбуке** (нужен Python, см. часть 4). Один раз:
```powershell
python "$HOME\Desktop\vault_sync.py" --url https://ТВОЙ-АДРЕС --vault "C:\Users\ТВОЁ_ИМЯ\iCloudDrive\Obsidian\SecondBrain"
```
Токен шлюза (`CAPTURE_TOKEN`) нужно перед этим задать в той же сессии: `$env:SECOND_BRAIN_TOKEN = "ТВОЙ_ТОКЕН"`. Чтобы скрипт работал постоянно, добавь `--loop 300` (проверка каждые 5 минут) и оставь окно PowerShell открытым. Автозапуск при включении ноутбука настроим отдельно, если захочешь.

**На телефоне.** Команда «Забрать из Telegram» (расписана в начале следующей сессии: она берёт `GET /pending`, сохраняет файлы так же, как «Во Второй Мозг», и отправляет `POST /ack`). Её удобно запускать автоматизацией при открытии Obsidian.

## Часть 6. Профиль, новые люди, интервью и напоминания в iPhone

### Что хранит сервер
Только то, без чего бот не узнает твоё окружение: **короткий профиль** (до 8000 символов), **имена известных людей с ролью и псевдонимами** (без телефонов и заметок). Посмотреть: `GET /profile`, стереть всё: `DELETE /profile` (с заголовком `x-api-key`). Ещё есть **срез хранилища** (часть 8) и очередь Telegram до выгрузки. Полных текстов заметок на сервере нет.

### Профиль для ИИ
1. В хранилище есть файл `Профиль.md`. Заполни его коротко и своими словами: кто ты, семья (кто как зовётся), дом и УК, работа, твои сокращения, правила. **Без паролей и номеров документов.**
2. Отправь его на сервер вместе со списком людей из `1-Люди` (на ноутбуке, Python как в части 4):
   ```powershell
   $env:SECOND_BRAIN_TOKEN = "ТВОЙ_ТОКЕН"
   python "$HOME\Desktop\vault_people.py" "ПУТЬ_К_SecondBrain" --push https://ТВОЙ-АДРЕС
   ```
3. С этого момента ИИ при каждой записи видит профиль и имена: «позвони жене» превратится в «Позвонить Диане», а «Серику» в канонического «Серик». Повторяй шаг 2 после заметных изменений.

### Новые люди (в Telegram)
Если в записи упомянут человек, которого нет в списке, бот после сохранения спросит: «Кто такой(ая) Серик?». Ответь одним сообщением («друг, работает в банке, 8 707…, ДР 5 марта»), и появится его карточка, а бот запомнит имя и роль. `/skip` пропускает. Если вместо ответа пришлёшь новую мысль или ссылку, вопрос просто снимается. Список известных людей: `/people`.

### Интервью: заполнить базу о себе за пару вечеров
Напиши боту `/interview`. Он задаст 60+ вопросов по блокам (ты, семья, люди, специалисты, дом, работа, учёба, документы, деньги, транспорт, здоровье, отдых, поездки, покупки, цели, ценности, цифровая жизнь, правила). Всё сразу не нужно: `/interview блоки` покажет список, `/interview дом` пройдёт только один блок, `/interview все` начнёт сначала. Отвечай как удобно, хоть обрывками. `/skip` пропускает вопрос, `/stop` ставит на паузу, `/interview` продолжает с того же места. Как это работает теперь:
- **Отказы не пишутся.** Ответы вроде «нет», «нет таких», «не знаю», «пока ничего» бот пропускает и в базу не кладёт.
- **Из ответа берутся только конкретные сущности:** человек, документ со сроком, техника, дело, место, поездка, цель. Общий пересказ ответа в заметку не превращается. Бот в ответ показывает, что именно записал.
- **Сырые ответы не теряются.** Когда блок закончен, они собираются в одну заметку «Интервью — Дом» (вопрос и ответ, без обработки ИИ). Это источник, из которого можно перепроверить извлечённое.
- В блоке «Оригинал» у извлечённых заметок остаются только твои слова, без служебных подсказок.
- Ответ с `!` сохраняется без ИИ и в сводную заметку блока не попадает.
Так можно разбить интервью на несколько вечеров. Забирай заметки шорткатом «Забрать из Telegram» (часть 11) или на ноутбуке (`vault_sync.py`) и проверяй в `0-Inbox`.

### Напоминания и события в iPhone
Сервис сам не будит тебя, он **подсказывает** шорткату, какие напоминания и события создать. В ответе есть список `reminders`: у каждого `title`, `kind` (`reminder` или `event`), `start` («2026-10-14 10:00», если времени не было, то 09:00) и для событий `end`. Берутся даты из срока дела, события, звонка, ухода по дому, срока документа (за 14 дней до конца), решения на пересмотр и т.д.

Добавь в конец шортката «Во Второй Мозг» (после сохранения файлов):
1. **«Получить значение для ключа»** → `reminders` из `v_response`.
2. **«Повторить с каждым элементом»**. Внутри (везде источник «Элемент повторения»):
   1. **«Получить значение для ключа»** → `kind`, затем **«Задать переменную»** `v_kind`.
   2. **«Получить значение для ключа»** → `title` → переменная `v_title`.
   3. **«Получить значение для ключа»** → `start` → **«Получить даты из входных данных»** → переменная `v_start`.
   4. **«Если»** `v_kind` **равно** `event`:
      - **«Получить значение для ключа»** → `end` → **«Получить даты из входных данных»** → `v_end`.
      - **«Добавить новое событие»**: название `v_title`, начало `v_start`, конец `v_end`, нужный календарь.
   5. **«Иначе»**: **«Добавить новое напоминание»**: название `v_title`, «Напомнить» `v_start`, нужный список.
   6. **«Конец Если»**.
3. **«Конец повтора»**.

Если «Получить даты из входных данных» не распознаёт формат, перед ним добавь действие **«Текст»** с `start` и пришли мне скриншот, подберём формат. Те же поля есть у каждого элемента очереди `GET /pending`, поэтому та же логика работает и для заметок из Telegram.

### Контакты iPhone → карточки людей
1. На ноутбуке открой icloud.com → **Контакты**, выдели всех (Ctrl+A), внизу слева шестерёнка → **«Экспорт vCard»**. Получится файл `.vcf`.
2. Положи рядом `vault_contacts.py` и `vault_people.py` (оба лежат в `tools/` репозитория) и запусти пробно:
   ```powershell
   python "$HOME\Desktop\vault_contacts.py" "$HOME\Downloads\Контакты.vcf" "ПУТЬ_К_SecondBrain" --dry-run

   Если контактов за годы накопилось много, берём только актуальные за последний год: добавь `--days 365`
   (контакты, менявшиеся за год) и при желании `--telegram "…\result.json"` (экспорт Telegram Desktop → Настройки →
   Расширенные → Экспорт данных, только личные чаты, формат JSON): добавятся все, с кем была переписка за этот срок.
   ```
3. Если всё устраивает, запусти без `--dry-run`. Для каждого контакта появится карточка в `1-Люди` с телефонами, почтой, компанией, должностью, днём рождения и адресом. Существующие карточки только дополняются. Потом снова `vault_people.py ... --push`, чтобы сервер узнал имена.

### Календарь и Напоминания iPhone → хранилище (разово или раз в месяц)
Команда **«Импорт календаря»** (создай в «Командах»):
1. **«Найти события календаря»**: начало «находится в следующие 60 дней».
2. **«Повторить с каждым элементом»**. Внутри:
   1. **«Форматировать дату»** для «Начало» → формат «Другой» `yyyy-MM-dd'T'HH:mm` → переменная `v_start`.
   2. **«Форматировать дату»** для «Конец» → тот же формат → `v_end`.
   3. **«Форматировать дату»** для «Начало» → формат `yyyyMMdd-HHmm` → `v_key`.
   4. **«Текст»** (весь блок целиком):
      ```
      ---
      schema: 1
      title: "[Название]"
      summary: "Событие из календаря"
      type: "event"
      status: "запланировано"
      stage: "processed"
      area: "разное"
      event_at: [v_start]
      event_end: [v_end]
      location: "[Место]"
      source: "ios"
      ---
      ```
      Вместо `[Название]` и `[Место]` вставь одноимённые свойства «Элемента повторения», вместо `[v_start]`/`[v_end]` переменные.
   5. **«Задать имя»**: имя `cal-[v_key].md` для этого текста.
   6. **«Сохранить файл»** в `SecondBrain/Календарь`, **«Перезаписать, если существует»** — **включено** (повторный запуск не плодит дубли).
Для напоминаний сделай такую же команду на базе **«Найти напоминания»** (не завершённые): `type: "task"`, `status: "открыто"`, `due: [срок]`, имя файла `rem-[название].md`, папка `0-Inbox`.

Это ручная сборка по описанию. Названия действий на твоей iOS могут слегка отличаться. Если что-то не находится, пришли скриншот.

## Часть 7. Секретарь: обзор недели, брифинг перед встречей, финансы «Ады»

### Обзор недели (без ИИ)
Тот же шорткат, что «Сводка дня», но в теле запроса добавь третье поле `mode` = `week` (тип «Текст») и адрес оставь `/digest`. Получишь: сколько записано за неделю и чего, просроченное, что впереди, кого жду, с кем давно не общался (больше 30 дней), решения на пересмотр, документы с истекающим сроком (60 дней), список «хочу», сколько во входящих и старых закладок. Удобно запускать по воскресеньям вечером через «Автоматизацию».

### Брифинг перед встречей
Новая команда «Брифинг». Действия как в «Спросить Второй Мозг», но: вопрос «С кем встреча?» сохрани в `v_person`, адрес `https://ТВОЙ-АДРЕС/brief`, поля тела `person` = `v_person` и `corpus` = `v_corpus`, в конце возьми ключ **`brief`**. Ответ: кто это, компания и роль, последний контакт, день рождения, идеи подарков, последние контакты и договорённости, открытые дела с этим человеком. ИИ не нужен.

### Финансы «Ады» в секретаре
Секретарь узнаёт про бюджет только агрегаты: доходы, расходы, баланс месяца, сравнение с прошлым, топ категорий и лимиты, долги и ближайшие сроки, подписки, цели. Отдельных трат он не видит. Тогда «Спросить Второй Мозг» отвечает на «сколько мы потратили на продукты?» и «кто мне скоро должен вернуть?», а «Сводка дня» и обзор недели получают строки про деньги.

Это два шага, оба необязательные; без них всё работает как раньше.

1. **Со стороны «Ады».** Изменения лежат в отдельной ветке `feature/secretary-summary` (pull request №2 в репозитории «Ады»), основная ветка не тронута. Проверь изменения и нажми **Merge**. Потом на Railway в сервисе «Ады» добавь переменную `SECRETARY_TOKEN` (длинная случайная строка, как `CAPTURE_TOKEN`). Пока переменной нет, новый адрес отвечает «не найдено» и ничего не раскрывает.
2. **Со стороны шлюза.** На Railway в сервисе шлюза добавь две переменные: `ADA_SUMMARY_URL` = `https://АДРЕС-АДЫ/api/secretary`, `ADA_SUMMARY_TOKEN` = тот же токен. Проверка: открой в Telegram или шорткатом `GET /finance`.

Если «Ада» недоступна, шлюз молча работает без финансов. Результат кэшируется на 5 минут. Сервер ничего из этого не сохраняет.

## Часть 8. Срез хранилища: бот отвечает, даже когда ноутбук выключен

### Что это
На сервере лежит **срез** твоего хранилища: у каждой заметки название, тип, статус, даты, люди, теги и одна короткая строка сути. **Полного текста нет.** Заметки с `!` и `private: true`, а также файлы без `type` в срез не попадают. Благодаря срезу бот и шорткаты отвечают без ноутбука и без чтения тысяч файлов из iCloud.

Срез пополняется двумя путями:
1. **Автоматически**: каждая запись через шорткат или Telegram сразу попадает в срез.
2. **Шорткат «Синхронизировать»** (раз в день или после больших правок в Obsidian): заменяет срез актуальным состоянием хранилища.

### Шорткат «Синхронизировать»
Сделай его как «Сводку дня» (части 3): действия 2–4 (папка **SecondBrain** → «Рекурсивно» → «Получить текст» → «Объединить текст» → переменная `v_corpus`), потом «Получить содержимое URL»: адрес `https://ТВОЙ-АДРЕС/snapshot`, метод **POST**, заголовок `x-api-key`, тело JSON с полем `corpus` = `v_corpus`. В конце «Получить значение для ключа» → `stored`, «Показать уведомление» с числом заметок.
Чтобы запускался сам: «Автоматизация» → «Время суток» → 23:00 ежедневно → «Выполнить команду» → «Синхронизировать».

### Команды в Telegram
- `/ask что я обещал Серику?` отвечает по срезу и показывает источники.
- `/day` сводка дня, `/week` обзор недели, `/brief Серик` что знать перед встречей, `/budget` бюджет из «Ады».
- `/sync` показывает, сколько заметок в срезе и когда была полная синхронизация.
- `/forget` стирает срез с сервера (потом он снова наполнится сам; полную копию вернёт «Синхронизировать»).

### Шорткаты стали быстрее
Теперь в «Спросить Второй Мозг», «Сводку дня» и «Брифинг» можно **не отправлять `corpus`**: сервис возьмёт срез. Удали шаги с чтением папки и оставь только `question` (или `person`, `mode`). Ответы придут за секунды. Если `corpus` всё же прислать, он используется вместо среза.

### Что сказать про приватность честно
В срезе есть названия твоих заметок, имена людей и даты. Это лежит в твоём сервисе на Railway под твоим аккаунтом. DeepSeek получает те же сжатые строки при вопросах `/ask`. Если что-то чувствительное, начинай запись с `!`.

## Часть 9. Дневник и вечернее напоминание

### В Telegram
- `/diary` запускает пять коротких вопросов: как прошёл день, что получилось, что не получилось, что завтра, за что благодарен. Отвечай голосом через диктовку или текстом. `/skip` пропускает вопрос, `/done` сохраняет уже рассказанное, `/stop` отменяет.
- Быстрее: напиши одним сообщением `дневник: сегодня закрыл вопрос с УК, устал, завтра звонить Серику`.
- Ответ с `!` делает всю запись приватной: она сохранится без ИИ.
- Из записи получится одна заметка `journal` за этот день (до 4 утра запись относится ко вчера) и отдельные дела `task` на завтра, если ты их назвал. Настроение пишется, только если ты сам назвал оценку дня.
- Настройки: `/diary время 22:00` (по умолчанию 21:00), `/diary выкл`, `/diary вкл`, `/diary статус`.

### Вечернее напоминание
**Вариант 1. Бот пишет первым.** Нужен токен бота: добавь на Railway переменную `TELEGRAM_BOT_TOKEN` (токен от BotFather, часть 5). Сервер раз в минуту проверяет время и, если в этот день записи в дневнике ещё нет, пишет тебе в Telegram «Как прошёл день?» Один раз в день, повторов нет.

**Вариант 2. Без токена, средствами iPhone.** Приложение «Напоминания» → **+** → «Дневник: как прошёл день?» → **«Время»** 21:00 → **«Повтор» → «Каждый день»**. Уведомление придёт в 21:00, открой Telegram и напиши `/diary`.

**Вариант 3. Шорткат «Дневник» (диктовка).** Создай команду: «Диктовать текст» (русский, «После паузы») → «Получить содержимое URL» на `https://ТВОЙ-АДРЕС/capture`, метод POST, заголовок `x-api-key`, тело JSON: `capture_id` (то же, что в «Во Второй Мозг»), `client` = `ios`, `content` = «Дневник: » и продиктованный текст. Дальше сохранение в Obsidian, как в основном шорткате. Запуск сам: «Автоматизация» → «Время суток» → 21:00 → «Выполнить команду».

Обзор недели показывает, сколько дней из семи ты вёл дневник.

## Часть 10. Голосовые сообщения в Telegram

Бот расшифровывает голосовое и дальше обращается с ним как с текстом: записывает мысль, отвечает на вопрос интервью или дневника. В ответе первой строкой покажет расшифровку, чтобы ты сразу заметил ошибки распознавания. Аудио нигде не сохраняется, на сервис речи уходит только запись. Для расшифровки нужен ключ сервиса речи. Самый простой вариант (бесплатный тариф есть):

1. Открой **console.groq.com**, зарегистрируйся (можно через Google) и в разделе **API Keys** нажми **Create API Key**. Скопируй ключ.
2. На Railway → проект **wholesome-prosperity** → сервис **web** → **Variables** → **New Variable**: `STT_API_KEY` = ключ. Подожди минуту, пока сервис перезапустится.
3. Отправь боту голосовое. Должна прийти строка «🎙 «…»» с расшифровкой и ответ, как на обычный текст.

Если захочешь OpenAI: `STT_API_KEY` = ключ OpenAI, `STT_BASE_URL` = `https://api.openai.com/v1`, `STT_MODEL` = `whisper-1`.
Ограничения: голосовое до 5 минут и до 20 МБ. Чтобы голосовое стало дневником, начни фразой «Дневник, …» или сначала отправь `/diary`: тогда голосовые пойдут как ответы на вопросы.

## Часть 11. Шорткат «Забрать из Telegram» (на iPhone, без ноутбука)

Заметки из Telegram ждут на сервере в очереди (до 45 дней). Шорткат кладёт их в `0-Inbox` и только потом стирает с сервера. Создай команду «Забрать из Telegram»:

1. **«Получить содержимое URL»**: адрес `https://ТВОЙ-АДРЕС/pending?limit=50`, метод **GET**, заголовок `x-api-key` = токен. Результат сохрани: **«Задать переменную»** `v_q`.
2. **«Получить значение для ключа»** → `items` из `v_q`.
3. **«Повторить с каждым элементом»**. Внутри цикла, везде источник «Элемент повторения»:
   1. «Получить значение для ключа» → `markdown` → «Задать переменную» `v_md`.
   2. «Получить значение для ключа» → `filename` → «Задать переменную» `v_name`.
   3. «Задать имя» `v_name` для `v_md`, затем «Сохранить файл» в iCloud Drive → Obsidian → SecondBrain → **0-Inbox** (как в части 2, шаг 5; «Спрашивать, где сохранить» выключено).
   4. «Получить значение для ключа» → `id` → «Получить содержимое URL»: адрес `https://ТВОЙ-АДРЕС/ack`, метод **POST**, заголовок `x-api-key`, тело JSON: поле `ids` типа **«Список»**, в нём один элемент типа «Число» = `id`. Так заметка стирается с сервера только после сохранения файла.
4. После цикла: «Показать уведомление» «Заметки из Telegram забраны».

Автозапуск: «Автоматизация» → «Время суток» → каждые несколько часов (например, 12:00 и 22:00) или «Когда открываю Obsidian» → «Выполнить команду» → «Забрать из Telegram», «Спрашивать перед запуском» выключено.
Это ручная сборка по описанию: если какое-то действие называется иначе, пришли скриншот.

## Часть 12. Бот пишет сам: утро, напоминания, неделя, «из прошлого»

Нужен токен бота на сервере (`TELEGRAM_BOT_TOKEN`, уже настроено) и срез хранилища (часть 8). Всё считается по срезу, без ИИ.

- **Утро (по умолчанию 08:30).** Сводка дня плюс блок «🕰 Из прошлого»: одна случайная старая идея, мысль или хотелка (старше 45 дней), чтобы они не пропадали. Если срочного нет и вспоминать нечего, бот промолчит.
- **Напоминания в срок.** Если у дела есть `remind_at` со временем (например, «напомни завтра в 15:00»), бот пришлёт сообщение в это время с кнопками **Через час**, **Завтра утром**, **Ок**. Для события напомнит за 30 минут. Дела только с датой попадают в утреннюю сводку.
- **Воскресенье, 19:00:** обзор недели (просрочено, жду ответа, давно не общались, документы, здоровье базы, бюджет «Ады», дневник).
- **Вечером:** напоминание про дневник (часть 9).
- **Настройка:** `/push` показывает, что включено. `/push утро 07:45`, `/push утро выкл`, `/push неделя выкл`, `/push напоминания выкл`.
- **Проверка базы:** `/health` ищет дубли, записи с тегами `unprocessed` и `проверить`, дела без срока старше месяца, давние входящие, карточки людей без роли, и ставит оценку из 100. `/remember` вспоминает старые идеи и хотелки по запросу.

Важно: кнопки меняют только время напоминания на сервере. Закрыть дело в хранилище по-прежнему нужно в Obsidian. Говори боту время словами: «напомни завтра в 15:00 позвонить Серику», ИИ поставит `remind_at`.

## Часть 13. Новое: поиск по смыслу, дубли, пересылки, повторы

- **Поиск по смыслу (бесплатно).** Когда заметок так много, что в ИИ уходит только часть, бот сначала просит ИИ придумать синонимы к вопросу («зуб» → «стоматолог», «пломба») и по ним отбирает заметки. Эмбеддинги и платные базы не нужны, ничего не хранится.
- **`/merge`.** Показывает группы похожих записей (то же название, та же ссылка, «Серик» и «Серик Ахметов») и какую оставить главной. Ничего не удаляет: слияние делаешь сам в Obsidian.
- **Пересылки.** Перешли боту сообщение, оно сохранится с пометкой «Переслано от …».
- **Фото и файлы.** Сохраняются как запись с подписью и пометкой о вложении, без вопросов. Сам файл в хранилище не попадает, и текст с картинок бот не читает: платного распознавания нет, а бесплатного хорошего нет. Пиши в подписи суть (сумма, срок), и она станет заметкой.
- **Повторяющиеся дела.** Скажи «поливать кактусы каждую неделю» или «отчёт раз в месяц»: ИИ заполнит `repeat`/`schedule`, и сводка дня покажет ближайшее будущее вхождение, а не «просрочено».

## Часть 14. Закрытие дел, мониторинг, резервная копия, PDF и проверка качества

**Кнопка «Сделано» закрывает дело в хранилище.** Раньше она только гасила напоминание. Теперь сервер кладёт в очередь служебную запись «закрыть дело», а `vault_sync.py` (на ноутбуке) находит заметку по названию и дате создания и меняет `status` на «сделано». Файл не удаляется. Если заметка не найдена, подходит несколько или она уже закрыта, запись просто пропускается и подтверждается на сервере. Запускай `vault_sync.py` как обычно (`2_vault_sync.bat`).

**Слияние дублей, закладки, большие хранилища.** `/merge` по-прежнему ничего не удаляет: по каждой паре пишет «оставить» и «объединить», а `/merge 1` готовит файл-подсказку для ручного слияния. В `/week` и `/health` появился отчёт «старые закладки без разбора» (считает код, без ИИ). Для тысяч заметок срез получил быстрый индекс по ключевым словам: `/ask` не замедляется, а полных текстов на сервере по-прежнему нет.

**Мониторинг.** Сбои обработчика Telegram, планировщика, DeepSeek, распознавания речи и «Ады» пишутся в лог структурной строкой `gateway_error` (только источник и тип ошибки, без текстов и без токенов). Если за час набралось три и больше сбоев, владельцу в личку приходит одно сообщение, следующее не раньше чем через час. `/status` показывает очередь, время последнего среза и последние сбои.

**Резервная копия.** `/backup` присылает в Telegram файл JSON с профилем и срезом (без текстов заметок, приватные в срез не попадают). Главный архив остаётся Obsidian в iCloud, а это копия того, что хранится только на сервере. Для команды нужна переменная `TELEGRAM_BOT_TOKEN`, она уже есть.

**PDF и картинки.** PDF с текстовым слоем (до 40 страниц, до 15 000 символов) читается локально библиотекой `pypdf`, текст идёт в запись с пометкой «PDF: имя файла», сроки размечает ИИ. Файлы нигде не сохраняются. Фото и сканы сохраняются с подписью, а бот честно пишет, что текст не распознан. Необязательно: если задать `VISION_MODEL`, текст с картинок будет распознаваться. По умолчанию через Groq и ключ `STT_API_KEY`. Можно взять другого провайдера, например Gemini: `VISION_API_KEY` (ключ из Google AI Studio), `VISION_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai`, `VISION_MODEL` (имя модели Flash из AI Studio). Для OpenAI: `VISION_BASE_URL=https://api.openai.com/v1`, `VISION_MODEL=gpt-4o-mini`, `VISION_API_KEY` — ключ OpenAI (данные API по умолчанию не используются для обучения). Бесплатный уровень Gemini может использовать присланное для улучшения продуктов Google, поэтому паспорта, договоры и сканы с личными данными так не отправляй (режим «!» картинки не отправляет вообще). Без переменной функция выключена, при любом сбое запись сохраняется как есть.

**Статусы лимитов** в `/budget` теперь по-русски.

**Проверка качества разбора.** В `tests/fixtures/eval_samples.json` лежат 25 типичных записей. Офлайн-тест проверяет, что код правильно нормализует ответы ИИ. Чтобы проверить реальный DeepSeek на этих записях, на ноутбуке задай `DEEPSEEK_API_KEY` и выполни `python tools/eval_samples.py`: скрипт напечатает таблицу совпадений типа и сферы. Без ключа он вежливо сообщит, что запускать не на чем.

## Часть 15. Заметки сами раскладываются и связываются

Работает на ноутбуке: `vault_sync.py` после каждой выгрузки запускает `vault_organize.py` (лежат рядом, тексты никуда не уходят).

- **Раскладка.** Новая заметка из `0-Inbox` со `stage: "inbox"` переезжает по типу: дела и события в `4-Дела`, идеи и выводы в `2-Знания`, медиа в `2-Знания/Медиа`, дом, документы, здоровье, поездки в `5-Дом и жизнь`, дневник в `6-Дневник/ГОД-МЕСЯЦ`. Переезжают только уверенные (`confidence` от 0.75, без тега «проверить»). Типы `note`, `bookmark` и `person` остаются на месте, чтобы человек их посмотрел. После переезда `stage: "filed"`; список лежит в `Дашборды/Разложено автоматически`.
- **Подстройка под тебя.** Если ты сам держишь заметки какого-то типа в своей папке (3 и больше, и это большинство), новые заметки этого типа едут туда же. Не нравится, куда уехала заметка, — перенеси её руками, система научится.
- **Связи.** В конец заметки записывается блок «Связано» со ссылками на родственные заметки вида `[[имя файла|Название]]`. Ищутся общие люди, общие «связанные» объекты, названия других заметок в тексте, общие теги и редкие слова. Блок служебный: он пересчитывается сам, остальной текст не меняется. Обратные ссылки Obsidian показывает сам.
- **Архив.** Закрытые дела, которые разложила система, уезжают в `3-Архив/ГОД`. Твои заметки без `stage: "filed"` не трогаются.
- **Карточки людей** (`vault_people.py`) создаются тоже автоматически, чтобы ссылки на людей вели на карточку.
- Приватные заметки (`private: true`) не связываются и не попадают в ссылки.

Ручной запуск: `python vault_organize.py "путь\к\SecondBrain" --dry-run` (только показать), без флага (сделать), `--all` (пересчитать связи у всех заметок и собрать `Дашборды/Здоровье связей`: заметки-сироты и битые ссылки). Отключить автозапуск: `vault_sync.py --no-organize`.

## Часть 16. Исходники: оригиналы всего, что ты присылаешь

Бот вытаскивает из записи смысл, но **оригинал остаётся с тобой**.

| Что прислал | Что сохраняется |
|---|---|
| Текст, ссылка, пересылка | Дословно в блоке «Оригинал» внутри заметки |
| Голосовое | Аудиофайл + расшифровка в блоке «Оригинал» |
| PDF | Сам PDF (и текст из него идёт в заметку) |
| Фото и скриншот (в том числе файлом без сжатия) | Картинка |
| Другой файл, аудио, видео, «кружок» | Файл как есть |

Файлы лежат в `7-Исходники/ГОД-МЕСЯЦ` в хранилище. В заметке появляется свойство `source_files` и раздел «Исходники» с `![[имя файла]]`: картинка, плеер или PDF открываются прямо в заметке. Если из одной записи получилось несколько заметок, все они ссылаются на один файл.

Как это устроено. **Из Telegram:** в очередь попадает только запись «исходник такой-то», а байты сервер не хранит: когда ноутбук выгружает очередь (`vault_sync.py`), сервер скачивает файл из Telegram и сразу отдаёт его ноутбуку. Пока файл не скачан, он остаётся в очереди (до 45 дней). **С шортката iPhone** (`POST /capture_file`): файл приходит на сервер, сервер распознаёт текст (картинка, голос, PDF), делает заметку и держит оригинал в очереди до выгрузки (не дольше 45 дней), после выгрузки стирает. Забирает исходники ноутбук (`vault_sync.py`) или телефон (`GET /pending?files=1`, затем `GET /file/ID`, затем `POST /ack`).

**Почему в `7-Исходники` пусто, хотя заметка есть.** Бывает три причины. (1) Оригинал отправляли обычным `/capture` (старый шорткат шлёт только текст): файла у сервера нет, переделай шорткат по разделу ниже. (2) Ноутбук не запускал `vault_sync.py` (`1_vault_sync.bat` или `4_vault_sync_loop.bat`): файлы лежат в очереди. Их видно на сервере: `GET /pending?service=1`, записи `kind` = `file`. (3) Распознавание картинок выключено (`VISION_MODEL`), поэтому в заметке только «вложение»: оригинал при этом всё равно сохраняется.

**Шорткат «Во Второй Мозг» с файлом (скриншот, фото, голос, PDF).** Для файлов используй отдельный запрос вместо `/capture`:
1. Действие «Преобразовать изображение» → в **JPEG** (iPhone иначе отдаёт HEIC, а сервер его не уменьшает и не читает).
2. «Закодировать» → **Base64** (без разрывов строк).
3. «Получить содержимое URL» на `https://ТВОЙ-АДРЕС/capture_file`, метод **POST**, заголовок `x-api-key`, тело **JSON** с полями: `capture_id` (то же, что в основном шорткате), `client` = `ios`, `filename` = имя файла, `mime` = `image/jpeg` (для голоса `audio/m4a`, для PDF `application/pdf`), `file_base64` = результат шага 2, `content` = подпись (необязательно; начни с `!`, и файл никуда не уйдёт, останется только оригинал).
4. Ответ тот же, что у `/capture`: заметки в `files`, плюс `recognized` (удалось ли прочитать), `file_notice` (что произошло) и `sources` (куда ляжет оригинал). Сохрани заметку как обычно. Вопросов по файлу сервер не задаёт: сохраняет как есть.
Размер файла до 20 МБ.

Ограничения: Telegram не отдаёт ботам файлы больше **20 МБ** (бот сообщит об этом, и такой файл нужно положить в хранилище руками); с шортката оригиналы приходят только через `/capture_file` (старый `/capture` шлёт один текст). Если за 45 дней ноутбук не включали, исходники из очереди пропадают.

**Бот молчит после смены токена.** Сервис сам сверяет вебхук Telegram со своим адресом при старте и раз в час (`app/webhook.py`) и при расхождении ставит его заново. Нужны `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` и адрес: `PUBLIC_URL` или `RAILWAY_PUBLIC_DOMAIN` (Railway задаёт его сам). После смены токена у @BotFather достаточно обновить `TELEGRAM_BOT_TOKEN` в Variables.

**Срез с ноутбука.** После каждой выгрузки `vault_sync.py` отправляет на сервер срез заметок (только блоки свойств, без текстов и без приватных), если он изменился. Так сводки и ответы бота видят раскладку, закрытые дела и склеенных людей. Отключить: `--no-snapshot`.

Контракт `POST /capture` (заголовок `x-api-key`) — тело: `capture_id`, `client`, `input_type` (`text`|`url`), `content`, `revision` (1|2), `user_clarifications`. Для старого шортката первый файл продублирован в `filename`/`folder`/`markdown`.

`POST /ask` — тело: `question`, `corpus` (склеенный текст заметок). ## Часть 17. Круги общения, `/who`, `/promises`, `/radar` и личные поля

- **`/who Имя`** (то же, что `/brief`, или `/кто`): досье перед встречей — кто это, круг, семья, последние контакты, открытые дела и обещания.
- **`/promises`** (`/обещания`, `/долги`): открытые дела с полем `promise`: «я» — я обещал, «мне» — мне обещали. Бот сам ставит его, когда в записи есть «пообещал…» или «обещал мне…».
- **`/radar`** (`/радар`): люди, с кем давно не общались. В карточке человека задай `orbit` (0 семья, 1 ближний, 2 соратники, 3 эксперты, 4 сеть) и, если нужно, `cadence_days`. Без своего срока берётся по кругу: 3 / 14 / 30 / 90 / 180 дней. Дата последнего контакта берётся из `last_contact` и записей типа `interaction`.
- В карточке есть `partner` и `children`.
- **Личные поля остаются у тебя.** `triggers`, `taboo_topics`, `persuasion_style`, `private_notes`, `psychology` в карточке (и всё, что ты пишешь в тексте заметки) не уходят на сервер: `vault_sync.py` вырезает их из среза, ИИ их не просит и не заполняет. Заполняй их руками в Obsidian.
- Отдельного графа в базе сервера нет: связи считаются из карточек и заметок, чтобы у данных был один источник — Obsidian.

## 18. Как бот ведёт диалог (чтобы ничего не терялось)

- У каждого чата сообщения обрабатываются строго по очереди: два быстрых сообщения не перепутают место в интервью.
- Место в интервью хранится отдельно. `/diary`, вопрос про человека или пауза его не стирают; `/interview` продолжит с того же вопроса, `/interview 22` перейдёт к вопросу 22.
- Вопрос «кто такой X» ждёт ответа 30 минут. Если в записи сразу несколько новых людей, спрашиваю про всех одним сообщением; про кого в ответе ни слова, спрошу отдельно. «Не знаю», «нет», `/skip` — пропуск (при нескольких людях пропускаются все).
- Пересылки, файлы и явные дела («купить молоко») после вопроса про человека считаются новой записью, а не ответом.
- Уточнение по записи ждёт 30 минут; не ответил — запись сохраняется как есть, бот сообщает об этом. «Не знаю», «как есть», «пропусти» тоже сохраняют без уточнений.
- Интервью и дневник без ответа 3 часа ставятся на паузу, и обычные записи снова идут как записи.
- Живые фразы: «давай дальше интервью», «стоп», «повтори вопрос», «назад», «сколько осталось».

## 19. Закрыть, отменить, перенести дело с телефона

Сводка (утренняя, `/day`, `/tasks`) нумерует дела, под ней ряд кнопок с номерами. Нажал номер: сообщение превращается в карточку дела с кнопками
«Готово», «Отменить» и вариантами переноса, подобранными по времени суток. Утром: через час, через 2 часа, после обеда, вечером, завтра, через неделю.
Поздно вечером: только завтра. «Своё время»: бот спросит «на когда?», ответ понимает по-русски («через 3 часа», «в 18:30», «завтра утром», «в пятницу», «25 октября»).
После действия сообщение само обновляется до свежего списка, чат не засоряется.

То же словами: «сделано 1», «сделано 1 и 3», «отмена 2», «отложи 3» (покажет варианты), «отложи 3 на 2 часа», «отложи 3 на пятницу», «сделано купить молоко» (по названию, если оно однозначное).
Командами: `/done 1`, `/cancel 2`, `/snooze 3 в 18:00`.

- Перенос на час или несколько часов ставит напоминание (`remind_at`): в это время бот сам напишет в Telegram. Перенос на день меняет только срок.
- Срез на сервере обновляется сразу: закрытое пропадает из сводок и напоминаний, даже если ноутбук выключен.
- В хранилище изменение приходит служебной записью. Её применяет `2_vault_sync.bat` на ноутбуке (меняет `status`, срок или `remind_at` в свойствах заметки). Телефонный шорткат такие записи не получает.
- Повторяющееся дело («каждые две недели») по «сделано» не закрывается навсегда, а переносится на следующий раз. «Отмена» закрывает всю серию.
- Номера относятся к последнему показанному списку и действуют двое суток. Потом бот попросит открыть `/tasks`.
- Свой день рождения в сводке не показывается (карточка «— профиль» или отношение «я»).

## Часть 20. Перенос списка «Дом» из «Ады»

Команда `/import дом` (или `/импорт дом`) забирает у «Ады» список «Дом» (техника, растения, фильтры и когда за ними ухаживать) и кладёт во «Второй Мозг»:

- по заметке типа `home` на каждую задачу ухода (срок `next_due`, период «каждые N дней»; после «сделано» в сводке срок сам сдвигается);

Дат покупки и гарантий в «Аде» нет, они не придумываются: допиши их в общей заметке. «Ада» продолжает напоминать про дом сама, поэтому напоминания могут приходить от двух ботов, пока не выберешь один.

## 21. `/contacts`: разбор карточек людей по одной

После импорта контактов в `1-Люди` лежит много карточек, где известно только имя и телефон. Команда `/contacts` в Telegram берёт такие карточки по очереди (сначала те, где есть телефон или компания) и спрашивает: «кто это и откуда знакомы?».

- **Ответ текстом** (например, «сосед по даче»): ИИ дополнит карточку, бот переходит к следующей. Ответ с «!» в начале не уходит в ИИ.
- **⏭ Пропустить** (или `/skip`): карточка вернётся при следующем запуске `/contacts`.
- **🗑 Убрать в архив**: бот переспросит. После «Да, убрать» ноутбук при ближайшей синхронизации (`1_vault_sync.bat` или `4_vault_sync_loop.bat`) переносит файл в `3-Архив/Удалённые-контакты`. Файл не стирается, его можно вернуть руками. Из среза и списка людей на сервере карточка пропадает сразу.
- **⛔ Стоп** (или слово «стоп»): остановиться, продолжить можно командой `/contacts`.

Разобранные и убранные карточки больше не спрашиваются. Для архивации нужна свежая версия `vault_sync.py` на ноутбуке (она в `SecondBrainTools.zip`).

## 22. Меню команд по «/» и «кто я»

- **Меню команд.** При старте и раз в час бот сам ставит в Telegram список всех команд, поэтому по `/` в чате видны `ask`, `day`, `contacts`, `me` и остальные. Ничего настраивать у @BotFather не нужно.
- **Владелец.** Бот берёт имя и фамилию из твоего аккаунта Telegram и считает тобой «Владислав Маскевич» и «Маскевич Владислав» (порядок слов, регистр и «ё» не важны). Свою карточку он не спрашивает в `/contacts`, не ставит в «давно не общались», не напоминает про твой день рождения и не создаёт как нового знакомого. Сменить имя или добавить псевдоним: `/me Владислав Маскевич, Влад`. Посмотреть: `/me`.

## 23. Джарвис: на связи, замечает важное

Джарвис — это секретарь (бот Второго Мозга), который теперь знает не только заметки, но и жизнь семьи по таблице трат «Ады». Для этого «Ада» отдаёт ему блок `life`: крупные покупки за 3 недели и последние зарплату и премию. Нужно обновить Аду и держать настроенными `ADA_SUMMARY_URL` и `ADA_SUMMARY_TOKEN`.

- **Крупная покупка.** От 50 000 ₸ (техника от 30 000 ₸), кроме еды, кредитов, коммуналки, связи, подарков и красоты. Джарвис пишет, что именно попросить: для ремонта и услуг договор, акт и гарантию на работы; для техники чек, гарантийный талон и серийный номер; для мебели чек и гарантийные условия; для авто заказ-наряд. Кнопки: «📎 Пришлю документы» (присылай фото и PDF, они сохранятся как документы к покупке; закончил, напиши «готово»), «📅 Гарантия до…» (дата или «2 года»; напомню за месяц до конца), «⏰ Напомни позже» и «✖ Не нужно». Без ответа напомнит ещё дважды с интервалом 3 дня.
- **Доходы.** Пришла зарплата или премия: одно короткое сообщение.
- **Новости.** Раз в полчаса читает публичные ленты статусов Railway, GitHub, OpenAI и Anthropic (свой список: переменная `NEWS_FEEDS=Имя=https://адрес;Имя=https://адрес`, пустая строка выключает). Про безопасность (утечки, взлом, смена ключей) пишет сразу с пометкой 🔴 даже ночью, про обычные сбои только днём.
- **Тишина.** С 22:00 до 08:00 Джарвис молчит, кроме тревог про безопасность. Выключатели: `/push джарвис выкл`, `/push новости выкл`.
- **Кнопки напоминаний.** Теперь: «✅ Сделано», «⏰ Через час», «🌆 Вечером в 19:00» (после 17:00 вместо него «🗓 Через 3 дня»), «🌅 Завтра в 9:00», «🕐 Другое время», «🗑 Отменить».
- **/contacts.** Под каждой карточкой кнопки ролей одним нажатием: семья, друг, работа, сосед, услуги, родня, плюс «Пропустить», «В архив», «Стоп».

Что не проверено вживую: адреса лент статусов взяты из стандартных шаблонов (RSS/Atom) и на живых лентах не проверялись; если лента недоступна, Джарвис молча её пропускает.

## 24. Связи: карточка человека, контакты, события

- **`/person Имя`** — вся карточка одним сообщением: данные (телефон, компания, семья, интересы), последние контакты и договорённости, открытые дела и обещания, ближайшие и прошедшие события, что купить или подарить, документы и дела с этим человеком, и «следующий контакт до …» по его кругу (`orbit`) или `cadence_days`. Кнопки: «✅ Связались сегодня», «⏰ Напомнить через неделю», «➕ Добавить факт» (бот передаёт ИИ то, что уже известно из карточки, чтобы телефон и компания не терялись), «🔕 Реже напоминать» (раз в год).
- **Лента контактов.** Любая запись с типом «контакт» (звонок, встреча, переписка) с человеком из карточек сама двигает ему `last_contact`, поэтому «давно не общались» считается по реальным разговорам. Под `/radar` у самых просроченных кнопки «✅ Имя» (связались) и «🔕» (не напоминать часто).
- **Автосвязи.** Новое дело само привязывается к открытому проекту, если название проекта звучит в деле (поле `project`). Ставится только если поля ещё нет. Карточки вида «Eichholtz Рабочий» узнаются как «Eichholtz».
- **Склейка дублей.** `2_tidy_people.bat` (нужны свежие `vault_people.py` и батник из `SecondBrainTools.zip`) склеивает: карточки с меткой номера (Рабочий, Домашний, Мобильный, Work…) с основной карточкой; «Маскевич Владислав» и «Владислав Маскевич» (порядок слов). Карточку из одного имени («Ирина») с полной («Ирина Диз Алматы») сам не склеивает: это могут быть разные люди. Подтверждение: `ДА`, `Y` или `1`. Обычная синхронизация больше не создаёт новых карточек «Имя Рабочий» и перестановок, а вливает данные в уже существующую карточку. Другой номер сохраняется, метка попадает в заметки. Одинокая карточка с меткой не переименовывается. Заметки типа «человек» из `0-Inbox` и других папок (бот создаёт новую при каждом ответе про человека), если карточка уже есть или таких заметок о человеке несколько, батник переносит в `3-Архив/Люди-дубли` после того, как их данные перенесены в карточку. Одинокая заметка о человеке без карточки остаётся на месте. Так исчезает основная масса групп в `/merge`.
- **События с людьми.** Через 30 минут после конца события (или через 1,5 часа после начала, если конец не указан) бот один раз спрашивает «Как прошло?». Кнопки: «✅ Прошло, всё ок» (событие становится «состоялось», у участников обновляется `last_contact`), «📝 Записать итог» (одним сообщением: ИИ сделает контакт, дела и обещания), «❌ Не состоялось», «⏭ Не нужно». В тихие часы (22:00–08:00) вопросы не приходят. Выключатель общий с напоминаниями: `/push напоминания выкл`.

Не проверено вживую: кнопки и «как прошло» нужны проверки на реальных событиях; в тестах они проходят.

## 25. Архив заметок для Claude

`5_export_for_claude.bat` (из `SecondBrainTools.zip`) собирает на рабочем столе `SecondBrain-export-ГГГГ-ММ-ДД.zip`: только `.md` заметки, без приватных (`private: true` или «!» в начале), без `7-Исходники`, `Шаблоны`, `.obsidian`, вложений и файлов больше 200 КБ. Длинные номера (12 цифр и больше: ИИН, счета, карты) заменяются на «[номер скрыт]», телефоны остаются. Архив прикрепляется в чат с Claude: так он видит хранилище целиком без платного доступа к компьютеру.

## 26. Вопросы без команды

Вопрос к заметкам можно писать прямо в чат (или сказать голосом): «когда щелкунчик?», «что я обещал Серику?», «когда там вылет в Алмату?», «где мой паспорт?», «есть ли гарантия на пылесос». Бот узнаёт вопрос по первому слову (когда, что, кто, где, сколько, какой, есть ли, помнишь, почему и т. п.) и отвечает как на `/ask`, с источниками. Не считаются вопросами и сохраняются как обычно: длинные тексты (больше 160 символов или несколько строк), ссылки, пересылки, вложения, фразы вроде «что-то надо купить», «напомни купить молоко», утверждения со знаком вопроса, запись с «!» в начале. Если по вопросу ничего не нашлось, бот добавляет подсказку: ответь «сохрани», и эта фраза сохранится как обычная запись. Во время интервью, `/contacts` и других диалогов вопросы не перехватываются.

## 27. «Вышли файл билета»

Бот запоминает идентификаторы файлов, которые ты присылал ему (PDF, фото, скриншоты, документы), вместе с названием заметки. Сами файлы на сервер не копируются: Telegram хранит их у себя, бот просит его прислать файл тебе же. Фразы в повелительном наклонении («вышли мне файл билета на щелкунчик», «пришли договор с мебельщиками», «скинь чек на пылесос», «покажи билет») бот узнаёт как запрос файла и находит нужный по названию заметки и имени файла. Нашёл один: присылает. Нашёл несколько: кнопки на выбор. Не нашёл: честно говорит и не создаёт дело. «Выслать файл Диане» (инфинитив) остаётся делом.

- **Старые файлы** (присланные до этого обновления) бот не знает. Перешли сообщение с файлом ещё раз с подписью `…, только файл`, например «Билет Щелкунчик 5 декабря, только файл»: он запомнит файл без создания заметки.
- Файлы из приватных записей («!») не запоминаются. Список идентификаторов стирает `/forget`. Хранится не больше 400 файлов, старые вытесняются.
- Работает только с файлами, которые прошли через бота. Файлы из почты и с ноутбука так достать нельзя.
