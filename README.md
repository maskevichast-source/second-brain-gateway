# Second Brain Gateway — версия 2

Маленький сервис, который принимает от тебя мысль (текст или ссылку), просит DeepSeek разобрать её по схеме «Второго Мозга» и возвращает готовые `.md`-файлы. Файлы сохраняет в Obsidian твой iPhone-шорткат.

**Это отдельный проект, к финансовому боту «Ада» он не относится.**

## Как это работает

```
iPhone (шорткат) ──POST /capture──▶ сервис на Railway ──▶ DeepSeek
        ▲                                   │
        └──── готовые .md (files) ◀─────────┘
iPhone сам кладёт файлы в iCloud → Obsidian/SecondBrain/0-Inbox
```

Что важно знать:

- **Схема v1:** 22 типа заметок (фильм/книга, место, вещь, человек, дело, идея, решение, здоровье, документ…) и 13 сфер жизни. Подробности: `docs/schema.html`.
- **Одна запись — до 10 заметок.** «Серик посоветовал Дюну, а ещё надо позвонить маме» превратится в две заметки. Ответ содержит массив `files`.
- **Режим «без ИИ».** Начни запись с `!` или со слова `секрет:` — текст не уйдёт в DeepSeek, не будет читаться по ссылкам и не запоминается на сервере. Заметка просто сохранится как есть.
- **Ссылки читаются.** Для YouTube берётся название и канал, для остальных https-страниц — заголовок и описание (закрытые и внутренние адреса сервис не открывает).
- **Тексты на сервере не хранятся.** В базе лежит только готовый ответ на 24 часа, чтобы повторная отправка не тратила токены. Потом он стирается. Все заметки живут только в твоём хранилище.
- **Заметка не потеряется.** Если DeepSeek недоступен, заметка сохраняется «как есть» (тег `unprocessed`).
- **Имя файла, дату и свойства делает код, а не нейросеть**, поэтому ИИ не может сломать файл.

Пока поддерживаются **текст и ссылки**. Голос и фото шорткат превращает в текст сам; Telegram и ответы на вопросы по базе — следующие шаги.

## Обновление с версии 1 (если сервис уже работает)

Новых библиотек и переменных не нужно, ключи и токен остаются прежними.

1. Распакуй новый архив.
2. GitHub → твой репозиторий → **Add file → Upload files**. Перетащи **всё содержимое** папки (папки `app`, `tests`, `docs` и файлы рядом). Файлы с тем же именем заменятся. Нажми **Commit changes**.
3. Лишние старые файлы в `app` (если такие появятся) можно удалить через ⋯ → **Delete file**. Критично это только для файлов с тем же именем, а они заменяются сами.
4. Railway сам пересоберёт сервис (1–3 минуты). Статус должен стать зелёным.
5. Открой `https://ТВОЙ-АДРЕС/health`: `{"status":"ok"}`.
6. Старый шорткат продолжит работать: первая заметка по-прежнему приходит в `markdown`/`filename`. Чтобы сохранять **все** заметки из записи, переделай шорткат по части 2.

## Часть 1. Запуск на Railway (один раз, ~15 минут)

### 1.1. Положи проект на GitHub

1. Зайди на github.com → **New repository** → название, например, `second-brain-gateway` → поставь **Private** → **Create repository**.
2. На странице нового репозитория нажми ссылку **uploading an existing file**.
3. Распакуй архив с проектом и перетащи в окно **всё содержимое папки** (папки `app`, `tests` и файлы `README.md`, `requirements.txt`, `Procfile` и т.д.). Нажми **Commit changes**.

> Файл `.env.example` — просто образец, настоящих ключей в нём нет. Свои ключи на GitHub не загружай никогда.

### 1.2. Придумай токен доступа

Это пароль, по которому сервис узнаёт твой шорткат. Он должен быть длинным и случайным. На ноутбуке открой **PowerShell** и выполни:

```powershell
[guid]::NewGuid().ToString("N") + [guid]::NewGuid().ToString("N")
```

Получится строка из 64 символов. Скопируй её и временно сохрани в надёжном месте (например, в менеджере паролей). Это твой `CAPTURE_TOKEN`.

### 1.3. Создай сервис на Railway

Названия кнопок могут немного отличаться, смысл тот же.

1. railway.com → **New Project** → **Deploy from GitHub repo** → выбери `second-brain-gateway`. Railway сам определит Python и запустит сборку (команду запуска он возьмёт из файла `Procfile`).
2. Открой созданный сервис → вкладка **Variables** → добавь переменные:

   | Имя | Значение |
   |---|---|
   | `CAPTURE_TOKEN` | токен из шага 1.2 |
   | `DEEPSEEK_API_KEY` | твой ключ DeepSeek |
   | `DEEPSEEK_MODEL` | `deepseek-v4-flash` (если DeepSeek переименует модель, поменяй здесь) |
   | `DATA_DIR` | `/data` |
   | `APP_TIMEZONE` | `Asia/Almaty` |

3. Добавь **Volume** (постоянный диск), иначе база обнулится при каждом перезапуске: в проекте нажми **+ New** / правый клик по сервису → **Volume** → путь монтирования (Mount path) **`/data`**.
4. Вкладка **Settings** → раздел **Networking** → **Generate Domain**. Получишь адрес вида `https://что-то.up.railway.app`.
5. Дождись, пока деплой станет зелёным (Active/Success).

### 1.4. Проверь, что сервис жив

Открой в браузере `https://ТВОЙ-АДРЕС/health`. Должно появиться `{"status":"ok"}`.

Если вместо этого ошибка, открой в Railway вкладку **Deployments → View logs**. Самая частая причина: не задан `CAPTURE_TOKEN` или он короче 24 символов. Сервис при этом специально не запускается и пишет об этом в логе.

### 1.5. Тестовая заметка с ноутбука

В PowerShell (подставь свой адрес и токен):

```powershell
$h = @{ "x-api-key" = "ТВОЙ_ТОКЕН" }
$body = @{ input_type = "text"; content = "Проверка связи: купить кабель HDMI до пятницы" } | ConvertTo-Json
$r = Invoke-RestMethod -Uri "https://ТВОЙ-АДРЕС/capture" -Method Post -Headers $h `
     -Body ([System.Text.Encoding]::UTF8.GetBytes($body)) -ContentType "application/json; charset=utf-8"
$r.message
$r.files[0].markdown
```

Ожидаемо: сообщение вроде `Дело: Купить кабель HDMI` и готовый Markdown со свойствами, тегами и блоком «Оригинал». Если пишет `ИИ недоступен — заметка сохранена как есть`, сервис работает, но с DeepSeek что-то не так: проверь `DEEPSEEK_API_KEY`, баланс и имя модели.

## Часть 2. Шорткат «Во Второй Мозг» на iPhone

> ⚠️ **Токен будет внутри шортката.** Никогда не делись этим шорткатом (ссылка iCloud, маркетплейс, генераторы шорткатов) и не вставляй токен в чужие сервисы и нейросети. Если токен всё-таки засветился, замени `CAPTURE_TOKEN` в Railway на новый и поменяй его в шорткате.

Открой приложение **«Команды»** → **+** → назови команду **Во Второй Мозг**.

### Шаг 1. Откуда команда принимает данные

1. Нажми на название команды вверху → **Подробнее** (значок ⓘ).
2. Включи **«Показывать в меню Поделиться»**.
3. В строке «Принимает …» оставь только **Текст** и **URL-адреса** (остальное отключи).
4. Для пункта «Если нет входных данных» выбери **Запросить** (тип — текст). Тогда команда сама спросит, что записать, если запустить её с экрана.

### Шаг 2. Уникальный номер заметки

Он нужен, чтобы повторная отправка не создавала дубли.

1. Действие **«Дата»** (Текущая дата).
2. Действие **«Форматировать дату»** → формат **«Другой»** → `yyyyMMdd-HHmmss`.
3. Действие **«Случайное число»** от `100000` до `999999`.
4. Действие **«Текст»**: вставь в него переменные «Отформатированная дата», затем дефис, затем «Случайное число».
5. Действие **«Задать переменную»** → имя `v_id`, значение = результат «Текст».

### Шаг 3. Отправка на сервис

1. Действие **«Получить содержимое URL»**.
2. **URL:** `https://ТВОЙ-АДРЕС/capture`
3. Нажми «Показать больше»:
   - **Метод:** POST
   - **Заголовки:** добавь заголовок `x-api-key` со значением = твой токен.
   - **Тело запроса:** JSON. Добавь поля (кнопка «Добавить новое поле»):

     | Тип | Ключ | Значение |
     |---|---|---|
     | Текст | `capture_id` | переменная `v_id` |
     | Текст | `client` | `ios` |
     | Текст | `input_type` | `text` |
     | Текст | `content` | **«Входные данные команды»** |
     | Число | `revision` | `1` |

   Тип входа указывать не нужно: если пришла одна ссылка, сервис сам поймёт, что это ссылка.
4. Действие **«Задать переменную»** → `v_response` = «Содержимое URL».

### Шаг 4. Если ИИ просит уточнение

1. Действие **«Получить значение для ключа»** → ключ `needs_review_flag` из `v_response`.
2. Действие **«Если»**: «Значение словаря» **равно** `yes`.
3. Внутри «Если»:
   1. **«Получить значение для ключа»** → `review_text` из `v_response`.
   2. **«Запросить ввод»** (текст), в подсказку вставь результат шага выше. Ответ сохрани в переменную `v_answer`.
   3. Ещё раз **«Получить содержимое URL»**: настройки те же, что в шаге 3 (проще всего **продублировать** то действие), но изменённые поля: `revision` = `2`, и добавь поле Текст `user_clarifications` = `v_answer`. Поле `capture_id` остаётся тем же (`v_id`).
   4. **«Задать переменную»** → `v_response` = «Содержимое URL» (она перезапишет старый ответ).
4. **«Конец Если»**.

### Шаг 5. Сохранение всех заметок в Obsidian

В ответе сервиса есть список `files`: одна запись может дать от 1 до 10 заметок. Шорткат должен пройти по списку и сохранить каждую.

1. **«Получить значение для ключа»** → ключ `files` из `v_response`.
2. **«Повторить с каждым элементом»** («Повторить для каждого»). Внутри цикла три действия, и везде источник — **«Элемент повторения»** (Repeat Item), а не `v_response`:
   1. **«Получить значение для ключа»** → `markdown` из «Элемент повторения». Затем **«Задать переменную»** `v_md`.
   2. **«Получить значение для ключа»** → `filename` из «Элемент повторения». Затем **«Задать переменную»** `v_name`.
   3. **«Задать имя»**: в русском интерфейсе читается как «Задать имя **[имя]** для **[объект]**». В поле имени вставь переменную `v_name`, в поле объекта — `v_md`. Расширение `.md` уже есть в имени.
   4. **«Сохранить файл»**: «Спрашивать, где сохранить» выключено; папка iCloud Drive → **Obsidian** → **SecondBrain** → **0-Inbox**; «Перезаписать, если существует» выключено.
3. **«Конец повтора»**.
4. После цикла: **«Получить значение для ключа»** → `message` из `v_response` → **«Показать уведомление»**.

Если в «Сохранить файл» на устройстве не получается выбрать `v_md` как содержимое, поставь перед ним ещё одно «Задать переменную» и сохраняй результат «Задать имя» (его называют «Именованный файл»).

### Режим «без ИИ»

Начни фразу с `!` (например, `! пароль от домофона 4321`) или словом `секрет:`. Текст не пойдёт в DeepSeek и не останется на сервере, но заметка сохранится в хранилище. Уточняющих вопросов в этом режиме нет. Понимай, что до сервера текст всё равно доходит по защищённому каналу, просто сервис его не анализирует и не запоминает. Совсем секретные данные (номера карт, пароли от банков) лучше вообще не записывать через шорткат.

### Проверка

1. Запусти команду, введи: `Серик посоветовал фильм Дюна 2, надо позвонить маме`.
2. Должно прийти уведомление, а в `0-Inbox` появиться 1–2 файла.
3. Открой файл в Obsidian: сверху свойства (тип, статус, сфера, теги), ниже текст и свёрнутый блок «Оригинал».

Если файл сохранился как `.md.txt`, «Задать имя» не применилось: проверь порядок (имя — `v_name`, объект — `v_md`) и что оно стоит **перед** «Сохранить файл».

Если после ответа на уточняющий вопрос сервис возвращает ту же заметку, проверь, что во втором запросе `revision` = **число** 2, а не текст.

## Часть 3. Вопросы к хранилищу, утренняя сводка, голос и фото

> Как это устроено. Заметки хранятся только в твоём хранилище. Шорткат читает их из iCloud и **вместе с вопросом** отправляет сервису. Сервис отдаёт ИИ сжатый список, получает ответ и **ничего не сохраняет**. Заметки с `private: true` (записанные через `!`) отбрасываются сразу, ИИ их не видит. Обычные заметки при вопросе всё же уходят в DeepSeek, имей это в виду.
>
> Заметки, у которых нет свойства `type` (стартовая страница, дашборды, шаблоны), в вопросах не участвуют.

### Команда «Спросить Второй Мозг»

Создай новую команду с таким названием и добавь действия:

1. **«Запросить ввод»** → тип «Текст», вопрос «Что спросить?». Голосом можно, значок микрофона на клавиатуре. Ответ сохрани: **«Задать переменную»** `v_q`.
2. **«Получить содержимое папки»** → выбери папку **SecondBrain** (iCloud Drive → Obsidian). Включи **«Рекурсивно»**: она спрятана за «Показать больше». Если такого переключателя нет, выбери папку `0-Inbox`, а вторым и третьим таким же действием добавь `1-Люди` и `2-Знания`.
3. **«Получить текст из входных данных»** (результат предыдущего шага).
4. **«Объединить текст»**, разделитель **«Новая строка»**. Затем **«Задать переменную»** `v_corpus`.
5. **«Получить содержимое URL»**:
   - URL: `https://ТВОЙ-АДРЕС/ask`
   - Метод **POST**, заголовок `x-api-key` = твой токен.
   - Тело запроса: JSON, два поля типа «Текст»: `question` = переменная `v_q`, `corpus` = переменная `v_corpus`.
6. **«Получить значение для ключа»** → `answer`.
7. **«Показать результат»** (откроется окно с ответом). Можно добавить **«Произнести текст»**, чтобы телефон зачитал ответ.

Примеры вопросов: «какие фильмы планировал на вечер?», «что я обещал Серику?», «что надо сделать по дому на этой неделе?», «когда истекает договор аренды?», «что решил насчёт замка и почему?».

Если ИИ недоступен, команда не сломается, а покажет, что нашлось по словам из вопроса. В ответе также есть `sources_text`: список заметок, на которые опирался ответ. Его можно вывести отдельным шагом «Получить значение для ключа» → `sources_text`.

**Пределы.** Одновременно можно отправить до ~3 млн символов заметок (это несколько тысяч заметок). Если их больше, сервис сам отберёт подходящие по словам вопроса. Чтение тысяч файлов из iCloud на телефоне занимает несколько секунд, это нормально. Когда заметок станет заметно больше, мы вынесем индекс в один файл, и ответы станут быстрее.

### Команда «Сводка дня»

Она нужна именно против забывчивости: показывает просроченное, сегодняшнее и ближайшие 7 дней по делам, событиям, дням рождения, уходу за домом, срокам документов и гарантий, решениям на пересмотр, ожиданиям ответа. **ИИ не нужен**, сводку считает код по свойствам заметок, поэтому она работает всегда.

Действия те же, что в «Спросить», кроме двух отличий: пропусти шаги 1 и 6, в шаге 5 используй адрес `https://ТВОЙ-АДРЕС/digest` и отправляй только поле `corpus`; в конце возьми ключ **`digest`**.

Чтобы сводка приходила сама каждое утро: приложение «Команды» → вкладка **«Автоматизация»** → **+** → **«Время суток»** → 08:00, «Ежедневно» → действие **«Выполнить команду»** → «Сводка дня» → отключи «Спрашивать перед запуском». Результат лучше показывать **«Показать уведомление»**, а не окно.

Сводка опирается на свойства-даты. Поэтому хорошо диктовать сроки словами: «до пятницы», «через неделю»: ИИ переведёт их в даты.

### Голос и фото в «Во Второй Мозг»

Сервис принимает только текст, а превращает в текст сам шорткат средствами iPhone. В начале команды «Во Второй Мозг» (там, где сейчас «Если нет входных данных → Запросить») поставь **«Выбрать из меню»** с пунктами:

- **Написать**: «Запросить ввод» (текст) → результат в переменную `v_content`.
- **Продиктовать**: **«Диктовать текст»** (язык: русский, остановка: «После паузы») → `v_content`.
- **Сфотографировать**: **«Сделать фото»** → **«Извлечь текст из изображения»** → `v_content`. Подходит для чеков, визиток, страниц, записей на доске.
- **Из буфера**: **«Получить буфер обмена»** → `v_content`.

Дальше в «Получить содержимое URL» поле `content` бери из `v_content`. Распознавание речи и текста делает сам iPhone, на сервер уходит уже готовый текст. Если диктовка в твоём регионе недоступна, пользуйся микрофоном на клавиатуре в пункте «Написать».

## Часть 4. Карточки людей (на ноутбуке)

Когда в заметках появляется `[[Серик]]`, отдельной карточки у него нет. Скрипт `tools/vault_people.py` создаёт для каждого названного человека файл `1-Люди/Серик.md` и **собирает в него всё известное**:
- телефоны, почту, день рождения, компанию и другое из заметок типа «Человек» (то, что ты надиктовал о нём);
- внутри карточки Dataview сам показывает его дела, звонки и встречи, всё, где он упомянут, и идеи подарков.

Скрипт ничего не отправляет в интернет и не затирает то, что ты уже вписал. Тело карточки он не трогает, а заполняет только пустые поля. Его безопасно запускать сколько угодно раз.

### Один раз: поставить Python
1. Открой python.org/downloads, скачай установщик для Windows.
2. В первом окне установки **обязательно поставь галочку «Add python.exe to PATH»**, затем **Install Now**.
3. Открой PowerShell и проверь: `python --version`. Должно показать версию 3.x.

### Каждый раз, когда хочешь обновить карточки
1. Положи файл `vault_people.py` в любое место, например на рабочий стол.
2. Узнай путь к хранилищу. При установленном iCloud для Windows это обычно `C:\Users\ТВОЁ_ИМЯ\iCloudDrive\Obsidian\SecondBrain`. Путь можно скопировать из проводника.
3. Сначала пробный запуск, который ничего не меняет:
   ```powershell
   python "$HOME\Desktop\vault_people.py" "C:\Users\ТВОЁ_ИМЯ\iCloudDrive\Obsidian\SecondBrain" --dry-run
   ```
4. Если список разумный, запусти то же самое без `--dry-run`.
5. Подожди, пока iCloud синхронизирует новые файлы на телефон.

Частота: раз в несколько дней или перед важным разговором. Если нужно сделать это одним ярлыком, пришли мне, соберу `.bat`-файл.

## Часть 5. Telegram-бот (вход для записи)

Бот принимает от тебя текст и ссылки, как шорткат: сервис разбирает их по схеме и отвечает «Записал: …». Если нужно, переспрашивает (ответь одним сообщением или `/skip`). Режим «без ИИ» работает так же: начни сообщение с `!`.

**Как заметка попадает в хранилище.** Сервис не может писать в iCloud, поэтому готовые заметки ждут в **очереди** на сервере. Их забирает **ноутбук** (скрипт `tools/vault_sync.py`) или **телефон** (шорткат), кладёт в `0-Inbox`, и только после этого заметка стирается с сервера. Если никто не забрал, заметка удаляется через 14 дней. То есть тексты из Telegram лежат на сервере, пока не будут выгружены (это исключение из правила «ничего не храним»). Спрашивать базу голосом из Telegram нельзя: заметки в нём недоступны, для этого есть шорткат «Спросить Второй Мозг».

Голос и фото бот пока не принимает. Диктуй с клавиатуры телефона или пришли текст.

### Настройка (один раз, ~15 минут)

**1. Создай бота.** В Telegram найди **@BotFather** → `/newbot` → придумай имя и username (заканчивается на `bot`). BotFather выдаст **токен** вида `123456:ABC...`. Это пароль от бота: никому не показывай и не присылай в чат нейросетям. (Мне он не нужен: токен используется только при одной команде ниже.)

**2. Придумай секрет вебхука.** Это длинная случайная строка (латиница и цифры, от 16 символов). В PowerShell:
```powershell
[guid]::NewGuid().ToString("N")
```
Сохрани результат.

**3. Добавь переменные на Railway** (сервис → Variables):

| Имя | Значение |
|---|---|
| `TELEGRAM_WEBHOOK_SECRET` | строка из шага 2 |
| `TELEGRAM_ALLOWED_USER_IDS` | оставь пока пустой, заполнишь на шаге 5 |

Railway сам перезапустит сервис.

**4. Подключи бота к сервису.** Один раз выполни в PowerShell (подставь свой токен, секрет и адрес):
```powershell
$token  = "ТОКЕН_ОТ_BOTFATHER"
$secret = "СЕКРЕТ_ИЗ_ШАГА_2"
$url    = "https://ТВОЙ-АДРЕС/telegram/webhook"
Invoke-RestMethod "https://api.telegram.org/bot$token/setWebhook" -Method Post -Body @{ url = $url; secret_token = $secret }
```
Должно вернуться `ok : True`. После этого закрой окно PowerShell, токен нигде сохранять не нужно.

**5. Узнай свой Telegram ID.** Напиши боту любое сообщение. Пока список разрешённых пуст, бот ответит «Бот ещё не настроен. Твой Telegram ID: 123456789». Впиши это число в `TELEGRAM_ALLOWED_USER_IDS` на Railway (можно несколько через запятую, например для жены) и дождись перезапуска. Писать боту смогут только они, остальные будут проигнорированы.

**6. Проверь.** Напиши боту «купить кабель HDMI до пятницы». Должен прийти ответ «Записал: …». Команда `/status` покажет, сколько заметок ждут выгрузки.

### Как забирать заметки

**На ноутбуке** (нужен Python, см. часть 4). Один раз:
```powershell
python "$HOME\Desktop\vault_sync.py" --url https://ТВОЙ-АДРЕС --vault "C:\Users\ТВОЁ_ИМЯ\iCloudDrive\Obsidian\SecondBrain"
```
Токен шлюза (`CAPTURE_TOKEN`) нужно перед этим задать в той же сессии: `$env:SECOND_BRAIN_TOKEN = "ТВОЙ_ТОКЕН"`. Чтобы скрипт работал постоянно, добавь `--loop 300` (проверка каждые 5 минут) и оставь окно PowerShell открытым. Автозапуск при включении ноутбука настроим отдельно, если захочешь.

**На телефоне.** Команда «Забрать из Telegram» (расписана в начале следующей сессии: она берёт `GET /pending`, сохраняет файлы так же, как «Во Второй Мозг», и отправляет `POST /ack`). Её удобно запускать автоматизацией при открытии Obsidian.

## Часть 6. Профиль, новые люди, интервью и напоминания в iPhone

### Что хранит сервер
Только то, без чего бот не узнает твоё окружение: **короткий профиль** (до 8000 символов), **имена известных людей с ролью и псевдонимами** (без телефонов и заметок). Посмотреть: `GET /profile`, стереть всё: `DELETE /profile` (с заголовком `x-api-key`). Всё остальное лежит только в хранилище.

### Профиль для ИИ
1. В хранилище есть файл `Профиль.md`. Заполни его коротко и своими словами: кто ты, семья (кто как зовётся), дом и УК, работа, твои сокращения, правила. **Без паролей и номеров документов.**
2. Отправь его на сервер вместе со списком людей из `1-Люди` (на ноутбуке, Python как в части 4):
   ```powershell
   $env:SECOND_BRAIN_TOKEN = "ТВОЙ_ТОКЕН"
   python "$HOME\Desktop\vault_people.py" "ПУТЬ_К_SecondBrain" --push https://ТВОЙ-АДРЕС
   ```
3. С этого момента ИИ при каждой записи видит профиль и имена: «позвони жене» превратится в «Позвонить Диане», а «Серику» в канонического «Серик». Повторяй шаг 2 после заметных изменений.

### Новые люди (в Telegram)
Если в записи упомянут человек, которого нет в списке, бот после сохранения спросит: «Кто такой(ая) Серик?». Ответь одним сообщением («друг, работает в банке, 8 707…, ДР 5 марта»), и появится его карточка, а бот запомнит имя и роль. `/skip` пропускает. Если вместо ответа пришлёшь новую мысль или ссылку, вопрос просто снимается. Список известных людей: `/people`.

### Интервью: заполнить базу о себе за пару вечеров
Напиши боту `/interview`. Он задаст ~25 вопросов по блокам (ты, семья, люди, дом, работа, документы, деньги, здоровье, отдых, цели). Отвечай как удобно, хоть обрывками. `/skip` пропускает вопрос, `/stop` ставит на паузу, `/interview` продолжает с того же места. Каждый ответ превращается в заметки (люди, дела по дому, документы со сроками и так далее). Начни ответ с `!`, и он сохранится без ИИ. Так можно разбить интервью на несколько вечеров. Забирай заметки на ноутбук (`vault_sync.py`) и проверяй в `0-Inbox`.

### Напоминания и события в iPhone
Сервис сам не будит тебя, он **подсказывает** шорткату, какие напоминания и события создать. В ответе есть список `reminders`: у каждого `title`, `kind` (`reminder` или `event`), `start` («2026-10-14 10:00», если времени не было, то 09:00) и для событий `end`. Берутся даты из срока дела, события, звонка, ухода по дому, срока документа (за 14 дней до конца), решения на пересмотр и т.д.

Добавь в конец шортката «Во Второй Мозг» (после сохранения файлов):
1. **«Получить значение для ключа»** → `reminders` из `v_response`.
2. **«Повторить с каждым элементом»**. Внутри (везде источник «Элемент повторения»):
   1. **«Получить значение для ключа»** → `kind`, затем **«Задать переменную»** `v_kind`.
   2. **«Получить значение для ключа»** → `title` → переменная `v_title`.
   3. **«Получить значение для ключа»** → `start` → **«Получить даты из входных данных»** → переменная `v_start`.
   4. **«Если»** `v_kind` **равно** `event`:
      - **«Получить значение для ключа»** → `end` → **«Получить даты из входных данных»** → `v_end`.
      - **«Добавить новое событие»**: название `v_title`, начало `v_start`, конец `v_end`, нужный календарь.
   5. **«Иначе»**: **«Добавить новое напоминание»**: название `v_title`, «Напомнить» `v_start`, нужный список.
   6. **«Конец Если»**.
3. **«Конец повтора»**.

Если «Получить даты из входных данных» не распознаёт формат, перед ним добавь действие **«Текст»** с `start` и пришли мне скриншот, подберём формат. Те же поля есть у каждого элемента очереди `GET /pending`, поэтому та же логика работает и для заметок из Telegram.

### Контакты iPhone → карточки людей
1. На ноутбуке открой icloud.com → **Контакты**, выдели всех (Ctrl+A), внизу слева шестерёнка → **«Экспорт vCard»**. Получится файл `.vcf`.
2. Положи рядом `vault_contacts.py` и `vault_people.py` (оба лежат в `tools/` репозитория) и запусти пробно:
   ```powershell
   python "$HOME\Desktop\vault_contacts.py" "$HOME\Downloads\Контакты.vcf" "ПУТЬ_К_SecondBrain" --dry-run
   ```
3. Если всё устраивает, запусти без `--dry-run`. Для каждого контакта появится карточка в `1-Люди` с телефонами, почтой, компанией, должностью, днём рождения и адресом. Существующие карточки только дополняются. Потом снова `vault_people.py ... --push`, чтобы сервер узнал имена.

### Календарь и Напоминания iPhone → хранилище (разово или раз в месяц)
Команда **«Импорт календаря»** (создай в «Командах»):
1. **«Найти события календаря»**: начало «находится в следующие 60 дней».
2. **«Повторить с каждым элементом»**. Внутри:
   1. **«Форматировать дату»** для «Начало» → формат «Другой» `yyyy-MM-dd'T'HH:mm` → переменная `v_start`.
   2. **«Форматировать дату»** для «Конец» → тот же формат → `v_end`.
   3. **«Форматировать дату»** для «Начало» → формат `yyyyMMdd-HHmm` → `v_key`.
   4. **«Текст»** (весь блок целиком):
      ```
      ---
      schema: 1
      title: "[Название]"
      summary: "Событие из календаря"
      type: "event"
      status: "запланировано"
      stage: "processed"
      area: "разное"
      event_at: [v_start]
      event_end: [v_end]
      location: "[Место]"
      source: "ios"
      ---
      ```
      Вместо `[Название]` и `[Место]` вставь одноимённые свойства «Элемента повторения», вместо `[v_start]`/`[v_end]` переменные.
   5. **«Задать имя»**: имя `cal-[v_key].md` для этого текста.
   6. **«Сохранить файл»** в `SecondBrain/Календарь`, **«Перезаписать, если существует»** — **включено** (повторный запуск не плодит дубли).
Для напоминаний сделай такую же команду на базе **«Найти напоминания»** (не завершённые): `type: "task"`, `status: "открыто"`, `due: [срок]`, имя файла `rem-[название].md`, папка `0-Inbox`.

Это ручная сборка по описанию. Названия действий на твоей iOS могут слегка отличаться. Если что-то не находится, пришли скриншот.

## Для разработчика

```bash
python -m venv .venv && .venv\Scripts\activate      # Windows
pip install -r requirements-dev.txt
pytest                                               # 176 тестов, без сети
set CAPTURE_TOKEN=<не короче 24 символов>            # локальный запуск
uvicorn app.main:create_app --factory --reload
```

Переменные окружения: `CAPTURE_TOKEN` (обязательно), `DEEPSEEK_API_KEY`, `DEEPSEEK_MODEL`, `DEEPSEEK_BASE_URL`, `DATA_DIR`, `APP_TIMEZONE`, `LLM_TIMEOUT_SECONDS` (60), `RATE_LIMIT_PER_MINUTE` (30), `MAX_CONTENT_CHARS` (20000), `MAX_CORPUS_CHARS` (3000000), `ASK_BUDGET_CHARS` (80000), `TELEGRAM_WEBHOOK_SECRET`, `TELEGRAM_ALLOWED_USER_IDS`, `OUTBOX_TTL_DAYS` (14).

Контракт `POST /capture` (заголовок `x-api-key`) — тело: `capture_id`, `client`, `input_type` (`text`|`url`), `content`, `revision` (1|2), `user_clarifications`. Ответ: `schema`, `count`, `files` (`filename`, `folder`, `type`, `title`, `markdown`), `needs_review_flag` (`yes`|`no`), `review_text`, `review_questions`, `message`, `fallback`, `private`. Для старого шортката первый файл продублирован в `filename`/`folder`/`markdown`.

`POST /ask` — тело: `question`, `corpus` (склеенный текст заметок). Ответ: `answer`, `sources`, `sources_text`, `notes_total`, `notes_used`, `notes_omitted`, `private_skipped`, `fallback`. `POST /digest` — тело: `corpus`. Ответ: `digest`. Код: `app/vault.py` (разбор заметок), `app/ask.py` (сводка и вопросы). Ничего из присланного не сохраняется.

Профиль: `GET|POST|DELETE /profile` (`context` до 8000 символов, `people`: `[{name, role, aliases}]`). В `/capture` можно передать `context` и `known_people` прямо в запросе (тогда сервер ничего не запоминает). Ответ `/capture` содержит ещё `new_people` и `reminders`.

Telegram: `POST /telegram/webhook` (заголовок `X-Telegram-Bot-Api-Secret-Token`, без `TELEGRAM_WEBHOOK_SECRET` отвечает 404), `GET /pending?limit=` и `POST /ack {"ids":[…]}` (заголовок `x-api-key`). Код: `app/telegram.py` (диалоги), `app/interview.py`, `app/people.py`, `app/reminders.py`, `tools/vault_sync.py`, `tools/vault_people.py`, `tools/vault_contacts.py`.

Устройство: `app/schema.py` — единственный источник схемы (типы, поля, значения); из него строится промпт (`app/prompt.py`) и проверка ответа ИИ (`app/service.py`).
